# MHD: first-pass preparation and measured five-second target

The production limit remains **10 seconds**. Five seconds is a target, not an achieved phone benchmark.

The camera button now starts OCR worker loading while the user frames the date. Each image variant's canvas is created only when that variant is requested. Existing crop, contrast, rotation, character whitelist, variant ordering, consensus thresholds and uncertain-result handling are preserved. Every variant remains available to the fallback. The image bitmap is released on success, exhaustion or cancellation.

Diagnostics record native/OCR pass duration and whether a date candidate was present, without adding raw OCR or images to performance exports. `RESERVE_EXPIRY_CAMERA.performanceSummary()` and the existing measurement export report sample count, confirmed count, confirmed correctness, median/p95 completion time, completion within five seconds, confirmed correct results within five seconds, and timeouts. A result without explicit confirmation is never treated as correct. These are the last 100 completed measurements, not independent holdout accuracy; cancellations before completion may not be represented. The date-precision correctness contract is unchanged.

## Checks

`node tools/test-expiry-recognition-timeout.mjs` checks lazy creation, reuse of the first canvas, fallback availability, bitmap release, honest confirmation metrics, the ten-second deadline, cloud abort, manual edits and late-result protection. Existing date-format and overload checks remain passing.

A diagnostic first-pass check used 19 reviewed real photos on 10 October 2026, with system desktop Tesseract and a PIL approximation of the original-layout preprocessing. First-pass text contained 10 selected date candidates; 7 matched the confirmed date and precision. The unchanged before/after parser made exactly the same decisions on all 19 OCR outputs. Desktop OCR subprocess median was 273 ms, maximum 678 ms, excluding preprocessing and camera/worker startup. These numbers are **not** browser/phone latency, automatic acceptance, a model improvement or independent holdout accuracy. The development samples were not used to relax acceptance rules.

Phone measurements and more independently confirmed examples are still needed before shortening the production deadline. Raw photos and exports remain outside the public repository.
